# ADR 0003：发布自动化走「确定性 CDP 步骤机」，LLM 不进热路径

- 状态：已采纳（P1.2，2026-10-21 真机校准后定稿）
- 关联：[ADR 0001 基于 DSH](0001-base-on-dsh.md)、[ADR 0002 运行时契约](0002-p0-runtime-contract.md)
- 实现：[architecture.md §6.1](../architecture.md)、[architecture.md §13](../architecture.md)；代码 `packages/channel-cdp/src/publish.ts`、`packages/daemon/src/cdp-publish.ts`

## 背景

发布页（`https://www.goofish.com/publish`）自动化有三条候选路线：

1. **脚本模拟点击 + LLM 编排**：确定性脚本执行每一步，模型只在需要判断时介入；
2. **LLM 直接点击**：agent 看页面、决定下一个动作、循环直到发布完成；
3. **直接调后端接口**：绕过页面，直接打 mtop 发布接口。

约束来自仓库不变量与实测：

- daemon 不调 LLM（AGENTS §1.1）；写操作必须幂等（§1.2）；单账号串行、QPS ≤ 1（§1.3）；凭据脱敏（§1.4）。
- 发布页是 React 受控表单 + contenteditable 富文本 + 高德地址联想，DOM 随版本漂移：本轮实测已发生「描述 `textarea` → contenteditable」这种结构性变化（见 architecture §13）。
- 真机上唯一可用的取证手段是截图 + 回读 DOM；失败必须能说清「卡在第几步、期望什么、看到什么」。
- 生产域名有风控：非浏览器节奏的高频调用、异常点击序列都可能触发验证码/限流。

## 决策

1. **唯一写路径是确定性步骤机**（`publish.ts`）：打开发布页 → 上传图片 → 填文案 → 计价 → 价格/包邮 → 地址 → 必填预检 → 提交并验证。每步有超时、截图、回读校验；失败 fail-closed，**不自动重试**。
2. **LLM 只在三个非热路径位置出现**：
   - 校准期：读截图/回读值判断选择器是否命中（本次校准就是这么做的）；
   - 运行时诊断：拿到 `XianyuError` 后由 agent 归因，决定「重试 / 换地址 / 转人工」；
   - GUI 人工兜底：面板里人工接管一次发布。
3. **后端接口（mtop publish）不作主路径**：发布调用链尚未逆向完整（`docs/asset-extraction.md`），签名与风控参数不稳定。保留为将来「链路已验证 + 有幂等 uniqueCode + 小号灰度」时的加速通道，且任何情况下不得绕开幂等与限流。
4. **DSH 内置浏览器（bsk / BrowserSkill）不作主传输**：它的语义是「人/LLM 驱动标签页」，且本机扩展未连接（`0 browsers connected`）。P1.2 校准改用「Edge 专用 profile + `--remote-debugging-port=9222`」的裸 CDP。bsk 的定位是运行时人工兜底与 GUI 演示，不是 daemon 的执行器。

## 为什么

| 维度 | LLM 直接点 | 直接调接口 | 确定性 CDP 步骤机（采纳） |
| --- | --- | --- | --- |
| 确定性 | 低，同页两次结果可能不同 | 高 | 高（选择器 + 回读校验） |
| 时延 | 每步一次模型往返，秒级 | 毫秒级 | 实测 3.3–5.1s 全流程 |
| 单次成本 | 每次发布都要模型 token | 几乎为 0 | 0 |
| 可测性 | 只能端到端，难断言 | 可单测（但依赖逆向字段） | 步骤/选择器都可假页面单测（本轮 +13 例） |
| 失败定位 | 模型自述，不可靠 | 结构化错误 | 「第几步 + 期望 + 实际」 |
| 风控暴露 | 点击节奏像人，但请求频率不可控 | 高（无浏览器指纹） | 与真人操作同源，可控节奏 |
| 维护成本 | 提示词与页面同时漂移 | 字段一改全断 | 选择器一改只改一行 |

量化：一次发布约 10 步；若每步一次模型往返（3–10s），端到端 30–100s 且不可复现；步骤机实测 5.1s，且失败能精确停在「填写地址」而不是「发布失败了」。

## 代价与替换触发条件

| 需要 | 现在 | 何时换 |
| --- | --- | --- |
| 页面改版 | 选择器表（architecture §13）+ dry-run 回归 | 每次闲鱼发版后跑一次 dry-run 对截图 |
| 富文本/联想输入 | 注入 `Input.insertText` + 回读校验 | React/编辑器升级导致注入失效时，重新实验填写方式 |
| 类目/文案质量 | 页面 AI 先识别类目；草稿给 `category` 时由 `packages/channel-cdp/src/category.ts` 的 `stepSelectCategory` 点选并 `assertCategoryPublishable` 校验（见 architecture §13.5） | 页面改版导致下拉打不开时，重做「可信鼠标事件」实验 |
| 地址 | 只能从「常用地址/附近地址」匹配（CDP 下联想结果不回显） | 若某次真机验证联想回显可用，扩展为自由搜索 |
| 速度 | 浏览器串行发布 | 逆向补齐发布链 + 幂等验证后，接 mtop 作为加速通道 |
| 失败自愈 | agent 诊断 + 人工兜底 | 失败样本显示选择器漂移占多数、且人工成本更高时，做「agent 读截图修选择器」的半自动修复 |

## 验收（当前状态）

阶段、测试数字、类型检查覆盖与真发布记录以 [`docs/STATUS.md`](../STATUS.md) 为准，本文不复制会漂移的数字。

本 ADR 锁的是「CDP 步骤机是唯一写路径」这一决策；真机校准细节（选择器、类目支持矩阵、一次成功的真发布记录）见 architecture §13。**「跑通过一次」不等于稳定能力**：默认仍 dry-run，`BF_PUBLISH_SUBMIT=1` 才真提交。
