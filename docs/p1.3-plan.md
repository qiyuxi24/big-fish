## 1. 登录态：cookie 拿得到，但要会「续命」

### 1.1 已跑通的链路

1. 用户本机 Chrome/Edge 以 `--remote-debugging-port=9222` 启动并登录闲鱼；
2. `channel-cdp` 连 CDP，`Storage.getCookies`（Edge 155 移除了 `Network.getAllCookies`，已做降级）只取 `.goofish.com` 的 cookie；
3. daemon 用 core `CredentialStore` 以 AES-256-GCM 加密落盘到 `%LOCALAPPDATA%/bigfish/credentials/<unb>.cred.json`，密钥文件 `credential.key` 权限 0600；
4. 三个入口：CLI `pnpm daemon:import-account`、HTTP `POST /accounts/import`、插件 `xy_import_account`。

安全性：只写本机磁盘，不上传；日志里 cookie / `_m_h5_tk` / `tfstk` / `x5sec` / `Authorization` 一律 `[redacted]`（core 脱敏按子串匹配）；多账号按 unb 分文件隔离。

### 1.2 令牌自动刷新（✅ 已落地，`aa5aec1`）

- 事实（实测）：`_m_h5_tk` 值 = `<32位token>_<毫秒过期>`，有效期 2 小时。过期后调用返回 `FAIL_SYS_TOKEN_EXOIRED::令牌过期`，**但响应 Set-Cookie 仍然下发新的 `_m_h5_tk` / `_m_h5_tk_enc`**；合并后重签即可 `SUCCESS`（第一次失败、第二次成功，已用脚本验证）。
- 设计：`callMtop` 识别过期类 ret → 合并 Set-Cookie 变更字段 → 重签 → **最多重试一次**；仍失败抛 `AUTH_EXPIRED`。刷新结果通过 `onSessionUpdate` 回传，daemon 回写 CredentialStore，避免每次都要重新导入。
- 进一步：daemon 起一个低频「保活」任务（比如每 90 分钟调一次 `loginuser.get`），把令牌一直续在有效期内；失败才提示重新扫码/导入。

### 1.3 扫码登录与风控

- 扫码登录（✅ 已落地，`77e9c9f`）：`pnpm daemon:login` / `POST /accounts/login` → 打开登录页等用户扫码 → 轮询 `loginuser.get` 拿 `unb`，等到 `unb` + `_m_h5_tk` 齐备才自动导入凭据（默认超时 180s）。适合「本机第一次使用」。
- 遇到 `x5sec` / 滑块 / 安全验证：**不硬刚**。检测到风控页就停队列、截图、通知用户人工过一次，然后继续（这也是商业工具的做法）。
- cookie 失效的判定：连续 N 次 `AUTH_EXPIRED` → 熔断该账号写操作，标记待重新导入。

## 2. 取品：一个链接 → 商家 ID → 全部商品图文

### 2.1 接口链（全部真机验证）

```
商家主页: https://www.goofish.com/personal?userId=<sellerId>        → userId 就是商家唯一 ID
商品链接: https://www.goofish.com/item?id=<itemId>&categoryId=<cat> → 先查详情拿 sellerId
  mtop.taobao.idle.pc.detail       data{sellerId,itemId?} → data.sellerDO.sellerId / data.itemDO{desc,richTextDesc,imageInfos...}
  mtop.idle.web.user.page.head     data{self,userId}     → baseInfo{kcUserId,encryptedUserId,tags} + module.tabs.item.number + social + base
  mtop.idle.web.xyh.item.list      data{needGroupInfo,pageNumber,userId,pageSize:20}
                                     → data.cardList[*].cardData.detailParams{itemId,title,picUrl,imageInfos,soldPrice,postInfo,categoryId}
  mtop.taobao.idle.pc.detail       data{itemId}          → itemDO 全文/全部图
```

- 价格字段是「元」字符串（如 `"30"`），入库前按既有 `yuanTextToCents` 转整数分。
- 分页：`pageNumber` 递增，直到 `hasMore=false`；每页 20。
- 频率：读接口也要慢，单账号串行 + 每请求间隔 3–5s、指数退避；批量拉取放 daemon 任务队列，不阻塞 HTTP。
- 落库：`items` 表存 itemId/title/priceCents/categoryId/status/raw 摘要 + 本地图片缓存目录；图片下载走 CDN，注意带 Referer，格式保留原图（webp/png/jpg）。

### 2.2 合规红线（重要）

- 默认**只允许拉自己账号**（`page.head.self === true`）。拉别人的店必须先由用户显式输入 sellerId 并确认「这是我有权使用的素材」，且仅用于**选品参考/看行情**，不落入「搬运上架」流程——不搬运他人商品是业务红线。
- 商品描述、图片版权归原主；「一键搬家上架」的功能一律不做。

## 3. 文案 skill 集 + AI 生图

- 文案放在 **skill 层**（agent 侧），不放进 daemon：skill 提供「标题 ≤30 字 / 描述 4 段式（卖点-成色-规格-交易） / 5 个话题标签 / 类目变体」模板 + 输入输出 JSON 契约 + 违禁词红线（破解/盗版/共享账号/代充… 与 core.delivery 的红线词同源）；daemon 只消费结构化结果。
- 改写链路：原商品事实（标题/描述/参数/图片 OCR 可选）→ LLM 按 skill 改写 → JSON 校验 → 生成草稿文件 → 发布步骤机消费。
- AI 生图：插件装适配器（通义万相 / 即梦 / 豆包 Seedream / OpenAI images / Gemini），key 存 DSH settings，不落仓库；输出 1:1 首图 + 3:4 详情图，转 webp/png；**生成图必须标注「示意图」，不能用于伪装实拍**。详细对比见 `docs/copywriting-and-imagegen-plan.md`。
- 离线兜底：本机无 API key 时只做「裁剪/白底/加水印」这类确定性图片处理，不假装能生图。

## 4. 发布方式

### 4.1 通道矩阵

| 通道 | 形态 | 状态 | 适用 |
| --- | --- | --- | --- |
| CDP 步骤机 | 本机浏览器逐字段填 + 点击提交 | **2026-10-21 端到端真发布成功**（用户账号，itemId 1093817229436）；类目受网页端支持矩阵限制 | 个人号主路径 |
| mtop 发布接口 | 直调 REST | 未逆向（B 的发布调用链待还原） | 加速，签名/风控要求高 |
| 闲管家开放平台 | 官方 API（MIT 移植客户端已就绪） | 客户端在，缺凭证 | 有企业资质的商家 |

### 4.2 类目：已破局（A2 已落地）

实测：发布页会根据图片/文案**自动识别类目**；选中「网页版不支持发布」的类目时，分类下方**立刻**出现「网页版暂不支持发布此分类，请使用闲鱼APP扫码继续发布 点击展示二维码」（不必等提交）。

分类是 antd Select：值在 `.ant-select-selection-item` 的 `title`，触发器是 `.ant-select-selector`，选项是 body 级 `.ant-select-item-option`；**打开下拉必须用可信鼠标事件**（`Input.dispatchMouseEvent`），JS `el.click()` 无效。

- **A2 显式指定类目（已实现）**：`PublishDraft.category` → `packages/channel-cdp/src/category.ts` 的 `stepSelectCategory`：等 AI 识别落定 → 开下拉 → 点选目标类目 → 回读校验 → 命中「不支持」提示立即 `VALIDATION`（不点二维码、不靠提交去撞）。步骤顺序与选择器表见 `docs/architecture.md` §13.5。
- 网页端支持矩阵（实测）：电子资料 / 学习笔记 / 课业本 ✅；教材教辅 / 语言与兴趣培训 / 学习资料定制 / 文学 / 考研咨询 ❌；期刊杂志 / 生活百科 待重测。**不做全量白名单硬编码**：白名单会随平台变化失真，改为「选完看页面提示」的运行时判定。
- **A3 APP 扫码续发（兜底，未实现）**：检测到二维码提示就截图存盘、返回需要人工扫码，用户手机扫码完成；这是覆盖全部类目的唯一出路，但不属于全自动写路径，按 ADR 0003 只作人工兜底。
- **A1 换素材**只用于验证链路，不作为产品功能。

### 4.3 提交与验证（不得假成功）

1. 提交前必填预检（标题/图片/描述/分类/价格/地址），缺项直接失败；
2. 点击发布后最多等 20s：URL 变化 / 出现成功提示 / 商品管理列表出现新 itemId 三者任一才算成功；
3. 超时或出现「网页版暂不支持」「风控」等文案 → 失败并截图，记录页面提示原文；**不重试**（写操作幂等由 uniqueCode 保证，重试前先查库）。

### 4.4 地址填写

- 点「宝贝所在地」→ 弹窗有搜索框 + 「常用地址 / 附近地址」列表；
- **已知限制**：CDP 下搜索联想请求正常但候选列表不回显，所以当前只能匹配「常用地址/附近地址」里的条目（`matchIndex`：整串 includes，再退前 3 字前缀）。
- 打磨方案：① draft 的 `address` 支持「地址名精确匹配 + 别名表」（用户可配「家/公司」→ 常用地址项）；② 首次使用时把常用地址列表抓下来落库（`addresses` 表），发布时按库匹配；③ 兜底：匹配不到就 fail 并把候选列表返回给用户选；④ 远期可用 CDP Fetch 拦截拿到搜索接口，直接按坐标/地址串请求（待验证）。

## 5. 自动发货

### 5.1 触发源

- **IM 消息**：买家拍下/付款后闲鱼会给卖家发系统消息，`channel-im`（已提交 `7a01bbf`，现 38 tests）+ daemon 侧 IM 长连（P2.1 已接线，`BF_IM=1` 才连，见 STATUS §4.2）解析消息 → 命中规则 → 执行动作。需要 IM 长连（websocket）或轮询会话列表。
- **订单轮询**：mtop 订单列表接口（**待抓包**）；兜底方案是 CDP 打开「我卖出的」页面读订单状态。

### 5.2 规则引擎（已实现）

`packages/core/src/delivery.ts`：`matchDeliveryRule(text, rules, now, context)`，条件支持关键词/正则/买家等级/金额/时间段，动作 `send_card | send_text | handoff | reject`，按 priority 排序、缺上下文 fail-closed；`validateDeliveryRules` 硬拦红线词。21 个单测。

### 5.3 执行与幂等

- 每个订单生成 `uniqueCode = f(orderId, ruleId, accountId)` 落库；执行前查库，禁止盲目重放；
- 发货动作：虚拟商品走「发卡密消息 + 标记已发货/无需物流」，实物走快递单号；**具体接口待逆向**（A 的核心发货调用链未还原），过渡期用 CDP 点页面完成，先做「人工确认」模式；
- 失败 → 重试（退避 `min(60*2^(n-1),1800)` 秒，最多 3 次）→ 进人工队列，插件面板可见、可手动 ack/fail；
- 单账号写串行 QPS ≤ 1，与发布共用写桶计量。

### 5.4 分阶段

1. **P2.0（先能用）**：手动触发发货 + 规则建议（面板展示命中规则与建议文案），全部动作人工确认；
2. **P2.1**：订单轮询 + 自动发消息（`channel-im` 发文本/卡片），发货状态仍人工确认；
3. **P2.2**：自动确认发货（需逆向接口或稳定 CDP 路径）。
